# 💞 Dotyk — план розробки

> Джерело: нотатка Notion [«Застосунок для пар — ідеї та план»](https://app.notion.com/p/3f90e16f84658111aaf3ee2a4abe3b1a)

## Огляд

**Dotyk** — безкоштовний застосунок для пар на iOS і Android: допомагає пам'ятати, коли востаннє проводили час разом, планувати спільні моменти й зберігати спогади.

**Принципи**
- Усе основне безкоштовне назавжди, без реклами.
- У першій версії немає чату: замість нього листівки, реакції, коментарі.
- Платна підписка Plus дає додаткову зручність і ШІ, а не базові функції. Платить один, Plus отримують обидва.
- Paywall показуємо лише після того, як користувач сам натиснув на платну функцію.

## Стек і архітектура

| Шар | Технологія |
|---|---|
| Застосунок | React Native, Expo, TypeScript, expo-router |
| Анімації та жести | react-native-reanimated, react-native-gesture-handler |
| Стан | Zustand |
| Локальне сховище | MMKV (dev-build потрібен і так, тому обмеження Expo Go не заважає) |
| Безпечне сховище | expo-secure-store для ключа шифрування сесії (сама сесія — у зашифрованому MMKV) |
| Бекенд | **Supabase**: Auth, Postgres + RLS, Realtime, Storage, Edge Functions |
| Нагадування | expo-notifications |
| Віджети | Android: react-native-android-widget. iOS: нативний таргет, на пізнішому етапі |
| Підписки | RevenueCat |
| Шрифти | @expo-google-fonts: Unbounded (заголовки, числа), Manrope (текст) |
| Іконки | phosphor-react-native: `regular` для навігації, `duotone` / `fill` для акцентів |
| Анімації іконок | reanimated (натискання, пружинки), lottie-react-native для кількох ключових моментів |

**Чому Supabase (рішення прийнято):** реляційна модель добре підходить для даних пари (пара, події, відповіді), RLS обмежує доступ до даних лише двома партнерами, а Realtime і Edge Functions закривають синхронізацію та запити до ШІ. Безкоштовного тарифу вистачить на старт.

### Структура проєкту

Expo SDK 58 тримає маршрути в `src/app/`, імпорти через `@/` (`@/theme/...`, `@/components/...`).

```
src/
  app/
    (onboarding)/      вітання, вхід, запрошення пари
    (tabs)/
      index.tsx        головна: лічильник днів
      moments.tsx      «коли ми востаннє…»
      plans.tsx        бакет-ліст, ідеї побачень
      memories.tsx     стрічка спогадів
      settings.tsx     тема, сповіщення, пара, акаунт (вкладка «Профіль»)
    _layout.tsx        шрифти, ThemeProvider
  theme/               tokens.ts, ThemeProvider (useTheme)
  components/          Text, Card, Button, Counter, Icon
  store/               Zustand (couple, events, settings)
  services/            storage (MMKV), supabase, auth, notifications
  utils/               дати, форматування
```

### Дані: що локально, що синхронізується

**Принцип:** Supabase є єдиним джерелом правди для всього, що бачать обидва партнери. На телефоні тримаємо кеш, щоб застосунок відкривався миттєво й працював без мережі, і чергу змін, яка відправляється, коли мережа з'явиться.

**Лише на пристрої**

| Що | Де |
|---|---|
| Токени сесії | зашифрований MMKV, ключ у expo-secure-store |
| Тема (світла / темна / системна) | MMKV |
| Налаштування сповіщень цього телефона | MMKV |
| Прапорці онбордингу, остання відкрита вкладка | MMKV |
| Чернетки листівок і відповідей | MMKV |
| Кеш серверних даних і черга змін (outbox) | MMKV |
| Кеш фото | expo-image (дисковий кеш) |

**Синхронізується через Supabase**

| Що | Примітка |
|---|---|
| Профіль, пара, дата початку стосунків | |
| Важливі дати, «Коли ми востаннє…» і відмітки | Відмітки лише додаються, не редагуються, тому конфліктів немає |
| Відповіді на питання дня | Відповідь партнера сервер віддає лише після відповіді обох (RLS або RPC), а не приховує клієнт |
| Листівки, реакції, «тик», настрій дня | Видимість настрою залежить від налаштування приватності |
| Бакет-ліст, списки, ігри, бали | |
| Спогади та фото | Фото стискаються перед завантаженням у Storage, окремо зберігаються мініатюри |
| Капсула часу | Сервер не віддає вміст до дати відкриття |
| Статус Plus, лічильники ШІ-запитів | Лише на сервері, клієнт тільки читає |
| Push-токени пристроїв | Для сповіщень про дії партнера |

**Як працює синхронізація**
- Під час запуску показуємо дані з кешу, потім довантажуємо зміни з сервера
- Realtime-підписка на таблиці пари, поки застосунок відкритий
- Зміни застосовуються в інтерфейсі одразу (оптимістично), потрапляють у чергу й відправляються на сервер; невдалі запити повторюються
- ID записів генерує клієнт (UUID), щоб повторна відправка не створювала дублікати
- Конфлікти редагування: перемагає остання зміна за `updated_at`; видалення м'яке (`deleted_at`), щоб воно теж синхронізувалось
- Нагадування «Коли ми востаннє…» плануються локально на кожному телефоні й перераховуються після кожної синхронізації; про дії партнера (листівка, відповідь, реакція) приходить push із сервера
- Віджет читає готові значення (лічильник днів, «востаннє бачились») зі спільного сховища, яке застосунок оновлює після синхронізації

**Візуальний стиль: легко, тепло, в міру мило**
- Багато повітря: великі відступи, мало елементів на екрані, одна головна дія
- М'які форми: картки з радіусом 24, кнопки-пігулки, жодних гострих кутів
- Кольори: світлі теплі фони, акценти рожево-кораловим і фіолетовим, градієнт лише на головних місцях (лічильник, Plus)
- Іконки: округлі Phosphor; `duotone` у кольорах теми дає милоту без мультяшності
- Анімації: пружні, короткі (200–400 мс), лише у відповідь на дію; серце, яке «б'ється» на «тик», конфеті на виконаний челендж
- Ілюстрації для порожніх станів і онбордингу: прості лінійні або абстрактні форми (серця, хвилі, крапки) у кольорах палітри, без персонажів і маскотів
- Тексти: теплі, на «ти», коротко
- **Уникаємо:** мультяшних персонажів, надлишку емодзі, неонових кольорів, щільних інтерфейсів, «дитячих» шрифтів

**Чому не lucide-animated:** це іконки для вебу (React DOM + Motion, анімація на наведення мишею), у React Native вони не працюють. Phosphor м'якший за Lucide, має шість стилів і нативний пакет для React Native. Якщо стиль Lucide подобається більше, то `lucide-react-native` зі `strokeWidth` 2.25 — запасний варіант.

**Готово, коли:** тема перемикається в налаштуваннях, а в компонентах немає жорстко прописаних кольорів.
